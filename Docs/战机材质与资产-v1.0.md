# 战机材质与资产 v1.0

> 2026-11-19 · 改动：`js/v3/models.js`（fighterMaterial / instantiateFighter）、`js/v3/main.js`、新增 `assets/models/f16.glb`

## 1. 结论：暗不是光照问题

先做了一次排除法：把机身材质临时换成 `MeshBasicMaterial({ map })`，绕过所有光照直接输出贴图原色。

**结果依然是纯黑。**

这说明问题不在光照、不在曝光、不在 bloom，而在资产本身——baseColor 贴图就是 ≈0.05 的深灰涂装。
调光、加补光、改 metalness 都救不了，只能在反照率上动手。

顺带挖出一个死代码：

```js
// 原代码
if (m.color && !m.emissiveIntensity) m.color.multiplyScalar(2.1);
```

`emissiveIntensity` 默认值就是 **1**，取反恒为 `false`，**这个分支从来没执行过**。
就算执行也没用：`m.color` 是纯白，乘 2.1 仍然是白，救不了 0.05 的贴图。

## 2. 修复

`models.js` → `fighterMaterial()`，按材质类型分流：

| 材质 | 处理 | 依据 |
|---|---|---|
| 带 baseColor 贴图的蒙皮 | `color ×4.5`、`metalness 0.15`、`roughness 0.55`、`envMapIntensity 1.4` | 真实战机蒙皮是哑光聚氨酯漆，不是金属 |
| Glass（座舱盖） | `metalness 0.1`、`roughness 0.06`、`opacity 0.46`、`depthWrite off` | glTF 默认 metalness=1，玻璃按金属算＝不反光不透光的灰板 |
| 无贴图小件（起落架/喷口） | 只做 `metalness ≤ 0.55` 上限 | 避免反射不到环境发黑 |
| 敌机 | `color.multiply(0.82, 0.52, 0.46)` | 砖红，与玩家浅灰拉开，不靠亮度区分 |

**增益系数是实测标定的**：×4 是中灰有层次，×7 偏白，×11 冲成纯白丢细节。取 4.5。

## 3. F-16 资产

`assets/models/f16.glb` — 30,272 三角面 / 4 材质 / 3 张 PNG / 5.2 MB。

来源：Sketchfab `F-16 Fighting Falcon - Fighter Jet - Free` by **bohmerang**（f0b00989e5634764848ef2c235c64db5）。

接入要点：

- glTF 导入时 `metallicFactor` 未指定 → **默认 1.0**，不改就是纯金属黑。
- 节点自带 `F-16-landingOff_5`（收起）和 `F-16-landingOn_6`（放下）。飞行时隐藏 `landingOn*` 即可。
- **机头朝 X 轴，不是 Z 轴**（包围盒 `size.x=150.9 > size.z=93.9`）。原 `normalizeFighterModel` 写死 `rotation.y = PI`，
  导致飞机横着飞 90°——追尾视角下这点很容易被误读成"机头偏了一点"。现改为按长轴判断，X 轴补 90°。
- 没有副翼/襟翼/平尾分件节点，**做不了分件动画**（原隐身机有 `rudder_L/R` + `stabilator_L/R`）。
- 没有尾焰节点，在 `instantiateFighter` 里程序化补一个。

### 尾焰：位置、几何、马赫环

**位置是实测出来的，不是估的。** 把 airframe 的全部顶点换算到机体局部坐标，按 z 切片统计截面：

| 切片 | 顶点数 | 截面中心 y | 截面半径 |
|---|---|---|---|
| z=2.15 | 376 | -0.151 | 0.30 |
| z=2.40 | 520 | — | 0.37 |
| z=2.45 | 314 | — | 0.39 |
| z=2.50 | 6 | — | 0.45（仅剩垂尾）|

结论：**喷口唇口 z ≈ 2.45，截面中心 y ≈ -0.15**。
机身中轴并不在 y=0，之前写 `(0, 0, 2.38)` 就是"火焰浮在喷口上沿、差一截"的原因。

**几何为什么要自己写。** 第一版用 `ConeGeometry`，结果"喷口一片黑，看不见火焰"。真因不是方向，是层级变换：

```
flame (Group, position = 0,0,0)
  └─ cone (position.z = 2.68)   ← 火焰的实际位置在子物体上
```

而 `Game.js` 用 `exhaust.scale.set(boost, boost, boost * pulse)` 控制长度。
**group 的 `scale.z` 会把子物体的 `position.z` 一起乘掉**——实测局部 z 从 2.28~3.08 被压到 1.48~2.00，
而机尾在 2.65，整支火焰缩进机身内部被完全遮挡。

现在用自定义 `BufferGeometry`：锥体从 `z=0` 长到 `z=length`，`flame.position` 钉在喷口。
`scale.z` 只改变长度，起点永远不动。

**马赫环（shock diamonds）。** 真实加力焰里有一串横向亮环，间距基本固定、亮度沿轴向递减。
用 shader 在几何 z 轴上做周期调制，不需要额外的环状网格：

```glsl
float band  = 0.5 + 0.5 * sin(vT * uRingFreq - uTime * 5.0);
float rings = mix(1.0, 0.12 + 0.88 * pow(band, 6.0), uRingAmp);
```

- `pow(band, 6.0)` 把正弦削成尖峰，环外压到 0.12——对比不够就完全看不出"环"，只是一条均匀光带。
- `vT = position.z / uLength` 用**几何局部坐标**，所以 `scale.z` 改长度时环的分布不会变形（这也是不用 uv 的原因，自定义几何没 uv）。
- 边缘用菲涅尔软化，否则锥体边界是一条硬直线。
- 头部 4% 渐入：锥体起点那圈顶点法线朝径向，侧视会形成一道硬边亮环，像套了个圆箍。

**尺寸按真实比例定**：1 世界单位 = 3.45 m，F-16 加力焰约 4–5 m → 1.2~1.5 单位，约为机长的 30%。
内核 0.70、包络 1.00，巡航 `scale 0.72`、加力 `1.5`。

| 层 | 半径 | 长度 | 环频率 / 强度 | 作用 |
|---|---|---|---|---|
| 内核 | 0.078 | 0.70 | 26 / 0.90 | 白热焰心，马赫环清晰 |
| 包络 | 0.125 | 1.00 | 10 / 0.10 | 柔和外轮廓，几乎不带环 |

玩家用暖白+琥珀（`#fff3dc` / `#ff8c3a`），敌方偏红（`#ffd6b8` / `#ff3f18`）。
颜色从最早的青白（`#7ef6ff`）换掉——那个色相像等离子引擎，和灰色机身、暖色阳光不在一个世界里。

> 两个实现细节：`ShaderMaterial` 的 `vec3` uniform **不认 `THREE.Color`**，必须转成 `Vector3`；
> 时间相位用共享 uniform（`FLAME_TIME`）由 `Game.update()` 每帧推一次，避免每架飞机各存一份。

上线前可选路径：

1. **买断商业授权**：直接联系作者或在 Fab / CGTrader 买 F-16 商用授权（预算约 $30–150）。
2. **换 CC0 资产**：Poly Haven / Quaternius 无战斗机；Kenney 只有低模色块风格。
3. **自建**：Blender 按现有 30k 面级重拓扑 + 烘焙 PBR，约 3–5 人日。
4. **AI 生成**：summerengine 等站有 Free 协议的 F-16 GLB（text-to-3D），质量需实测。

> 建议路线：**原型期用当前资产跑通全部视觉与玩法，进美术阶段时按 1 或 3 处理。**

## 5. 顺带修掉的工具问题

`tools/shoot.mjs` 之前会连到**残留的旧 headless Chrome**（多个实例抢同一个 9333 调试端口），
表现是"改了代码但截出来的画面没变"，排查成本极高。

现在：随机端口 + 每次独立 `--user-data-dir` + 结束清理；另外支持 `SETUP_FILE=` 传多行 async 脚本。

`SETUP_FILE` 的脚本会被执行两次（等待前 / 截图前），**有累积副作用的操作要做幂等保护**——
有一次把火焰位置 `+= 1.2` 加了两遍，白白多排查一轮。
