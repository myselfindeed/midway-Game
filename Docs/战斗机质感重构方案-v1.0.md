---

## 0. 一句话结论

**当前"质感差"不是模型精度问题，而是渲染管线缺了三块地基：环境反射（IBL）、阴影、后处理。**
缺了 IBL 就不敢用金属材质，于是把机身压成 `metalness 0.1`（塑料参数）；压平之后又靠半球光 + 提曝光去"补亮"，结果越补越灰。**真正的解法是补齐这条因果链的上游，而不是继续调模型。**

## 2. 把"质感"拆成 6 个可实现的因子

参考图那种"金属味"，是 6 层叠加的结果，而且是**乘法关系**——任何一层缺失，整体都上不去。

| # | 因子 | 参考图里的表现 | 当前项目 | 差距 |
|---|---|---|---|---|
| L1 | 几何与轮廓 | 分件清晰（翼面/舵面/喷口独立），轮廓硬朗 | 13k 面、26 分件的 PBR 模型**已存在但没被加载**；实际加载的是 5k 面单 mesh 版本 | 中 |
| L2 | 材质通道 | 面板线、铆钉在斜光下清晰可见；机身有连续高光带；喷口是拉丝金属 | 只有 1 张 JPEG baseColor，**无法线、无 ORM、无 AO**；参数 `metalness 0.1 / roughness 0.68` | **致命** |
| L3 | 环境与光照 | 机身反射天空（上亮下暗），有自阴影，暗部偏冷、亮部偏暖 | 只有一个 hemisphere + 2 个方向光，**无 `scene.environment`、无 shadowMap** | **致命** |
| L4 | 后处理 | 喷口光晕溢出、边缘柔化、整体轻微调色与暗角 | 直接 `renderer.render`，**无 composer、无 bloom、无调色** | **致命** |
| L5 | 动态特效 | 尾焰分级（核心/外焰/冲击钻石）、翼尖涡流、热浪 | 一个半透明发光锥 + 一个 PointLight | 大 |
| L6 | 相机与构图 | 机位正后上方 ~22°，FOV 约 35–40°，战机占屏约 1/3 | 后 7.6 / 上 3.1，**FOV 60**，战机占屏偏小 | 中 |

## 3. 现状诊断（代码与资产证据）

### 3.1 材质参数是被迫妥协的结果

`models.js` 中战机实例化后没有任何材质定制，`fighter.glb` 自带：

```
paint : baseColorTexture(JPEG)  metalness 0.10  roughness 0.68   ← 这组参数 = 哑光塑料
nozzle: baseColorTexture(JPEG)  metalness 0.72  roughness 0.32
glass : baseColorTexture(JPEG)  metalness 0.55  roughness 0.08  alphaMode BLEND
```

`metalness 0.1` 的物理含义是"非金属"。而 reference 里的机身是**金属漆**（金属度约 0.4–0.6 + 清漆层）。
为什么当初会写成 0.1？因为**没有环境贴图时，metalness 越高画面越黑**——金属只反射环境，没有环境就什么都没有。这是典型的"缺 IBL 导致材质参数被反向拉平"。

### 3.2 光照结构是"平光"，天然消灭体积感

```
HemisphereLight(0xcfe9ff, 0x1d4e86, 1.35)   ← 主光强的竟然是环境光
DirectionalLight 1.35（无 castShadow）
DirectionalLight 0.45 fill
toneMappingExposure = 1.18
```

半球光 1.35 意味着**天空+地面给了 1.35 的均匀照度**，等于把所有朝向的表面都拉到同一亮度。金属质感 100% 依赖"不同朝向的表面亮度差"，平光下必然消失。同时 `renderer.shadowMap` 从未开启，机翼投不到机身上，座舱盖不投影，形体全靠轮廓线撑。

### 3.3 上一版更完整的模型被冷落

| | `assets/models/fighter.glb`（在用） | `assets/fighter.glb`（未用） |
|---|---|---|
| 三角面 | 5,060 | 13,269 |
| 材质 | 9 | 25（含内饰、起落架、航行灯、喷口内外壁） |
| 贴图 | 1 张 JPEG（115KB） | 3 张 KTX2：**Color / Normal / ORM** |
| 座舱 | 半透明 BLEND | `KHR_materials_transmission` 真玻璃 |
| 分件 | 单 mesh | 26 个 mesh，副翼/襟翼/方向舵/平尾可独立动画 |
| 压缩 | 无 | meshopt + basisu |

**双份资产并存本身就是一次架构事故**：同样的模型维护两套，代码里写死一套，预览页（`assets/models/preview.html`）用另一套。

### 3.4 启动流程的技术债

`main.js` 为了给 `KTX2Loader.detectSupport()` 传 renderer，额外 `new THREE.WebGLRenderer()` 建了一个"probe" 上下文，用完 dispose。移动端浏览器对同时存在的 WebGL 上下文数量敏感（iOS 上限很低），这既不必要也有 context lost 风险。根因是**启动顺序错了**：先加载资源、后创建渲染器，只好临时造一个。

### 3.5 性能上会踩的坑（虽然现在还没爆）

- 每架敌机 `clone(true)` 后**逐材质 clone**：13k 模型是 25 材质 × 26 mesh，7 个实例 ≈ 182 个 draw call、175 个材质对象。
- 尾焰 `PointLight` 每架一个（动态光在前向渲染里便宜，但跟后续加 shadow/transmission 会冲突）。
- 相机 `lerp(0.12)` 是**按帧插值**，不同刷新率下手感不一致（iPad 120Hz vs 手机 60Hz）。

## 4. 目标架构：把渲染从玩法里剥出来

现在 `Game.js`（750 行）同时管玩法、渲染器、光照、特效；`models.js`（507 行）同时管战机、舰船、海洋、天空、岛屿。质感要迭代，必须先把"渲染层"独立成可替换的子系统。

```
js/v3/
├── core/
│   ├── Game.js            仅玩法状态机 + 每帧 update 调度
│   └── Loop.js            固定步长逻辑 + 可变步长渲染，去帧率依赖
├── render/
│   ├── Renderer.js        WebGLRenderer / pixelRatio / toneMapping / resize / 上下文恢复
│   ├── Environment.js     天空盒 → PMREM 环境贴图 / 太阳 / 雾 / 曝光
│   ├── PostFX.js          composer 链：Render → Bloom → Output → 调色 → AA
│   ├── Quality.js         设备探测 + 三档画质 + 运行时自动降级
│   └── ChaseCamera.js     跟随相机（阻尼按 dt 计算）
├── assets/
│   ├── Loader.js          GLTF/KTX2/meshopt 单例 + 进度 + clone
│   └── Materials.js       材质工厂：战机漆面 / 座舱 / 喷口 / 舰船，敌我变体覆盖
├── models/
│   ├── fighter.js  ship.js  terrain.js  ocean.js  sky.js
├── fx/
│   ├── Afterburner.js  Contrail.js  Explosion.js
└── data/
    └── tuning.js          所有魔法数字（速度、相机偏移、材质参数）集中
```

关键边界：
1. **`models/*` 只产出 `Object3D`，不碰灯光、不碰后处理**（现在 `createSky` 还被 `updateCamera` 手动 `position.copy`，属于耦合）。
2. **材质参数全部走 `Materials.js`**，禁止在模型里写死。敌我区分改为"材质变体覆盖"，而不是现在的 `color.offsetHSL(0, 0.04, -0.16)`——那会把贴图上的机徽、警示色一起偏移掉。
3. **`tuning.js` 集中数值**，UI/调参时不必翻 750 行。

## 5. 六层改造怎么做（按收益排序）

### L3 环境光照 —— 单点收益最大，先做这个

1. 用 `PMREMGenerator` 把现有 `assets/textures/sky.jpg` 烘成环境贴图，赋给 `scene.environment`。
   好处：反射与背景天空**天然一致**，不需要额外 HDR 资源，也没有色调打架。
2. 半球光降到 0.25–0.4 或干脆删掉（IBL 已经提供天光）。
3. 太阳光升到 2.0–2.5，方向对齐天空贴图里的高光位置，`castShadow = true`，
   跟随玩家的正交阴影相机紧贴战机（半宽 6–8 单位），`PCFSoftShadowMap` + 微调 bias。
   **自阴影**（机翼压在机身上、座舱盖投影）是免费且巨大的形体细节。
4. 加 `FogExp2`，颜色取地平线色——让战机"坐进"大气里，而不是贴在图前。
5. 曝光从 1.18 降到 0.9–1.0。高光溢出交给 bloom，不靠整体提亮。

> 这一层做完，"塑料感"就会消失大半，因为 `metalness` 终于可以调回物理正确的 0.4–0.6。

### L2 材质 —— 换用已有的 13k PBR 资产

- 直接切到 `assets/fighter.glb`（自带 Normal + ORM），`KTX2Loader` 的 transcoder 改为**本地托管**（现在指向 `unpkg`，离线即挂，且多一次 RTT）。
- 漆面用 `MeshPhysicalMaterial`：`metalness 0.45 / roughness 0.35 / clearcoat 0.6 / clearcoatRoughness 0.12 / envMapIntensity 1.1`。
- 座舱：真 `transmission` 在移动端会触发额外一次场景渲染，建议**降级为 alpha + 强环境反射 + Fresnel**，视觉差异在跟随机位下几乎看不出，性能差 2 倍以上。
- 贴图规范：`anisotropy = 8`、`colorSpace` 区分（Color=sRGB，Normal/ORM=Linear）、mipmap 开启。
- 喷口：`metalness 0.9 / roughness 0.25` + 内部自发光，让它成为画面里的"金属锚点"。

### L1 几何 —— 分件用起来

13k 模型有 aileron / flap / rudder / stabilator 独立节点。哪怕只做**副翼随转向偏转、平尾随俯仰偏转**这两个自由度，运动中的质感提升也远超再加 10k 面。起落架节点保持隐藏即可（现逻辑已按名字过滤 `gear`）。

### L4 后处理 —— 光晕是"高级感"的主要来源

链：`RenderPass → UnrealBloomPass(threshold 0.85, strength 0.55, radius 0.4) → OutputPass → 调色 Pass → AA`

- r160 起**必须用 `OutputPass`** 承担 tone mapping + color space（否则 bloom 在 sRGB 空间做，颜色会脏）。
- bloom 用**半分辨率**，移动端成本可接受；HUD 是 DOM 层，天然不受 bloom 影响——这是本项目结构上的优势。
- 调色：轻微 S 曲线对比 + 暗部偏冷 + 饱和 −5%。参考图的"高级灰"很大程度来自这一步。
- 抗锯齿：composer 会关掉默认 MSAA，需显式给 RenderTarget 设 `samples: 4`（WebGL2），否则机身边缘会有明显锯齿，反而比现在更廉价。

### L5 动态特效 —— 尾焰要"分层"

参考图的喷口其实是 3 层：**白热核心（HDR>1）+ 蓝色外焰 + 冲击钻石（shock diamonds）纹路**，再叠一层加法混合的 sprite 做光晕，最后让 bloom 去溢出。
再加：翼尖涡流（细长条带，宽度随过载变化）、高速时的热浪扭曲（可选）、受损时的黑烟。

### L6 相机 —— 便宜且立竿见影

FOV 60 → 45–50，跟随机位后 6.2 / 上 2.6（保持 22° 俯角），战机占屏从约 1/5 提到约 1/3。
同时把 `lerp(0.12)` 改成 `1 - exp(-k*dt)`，保证 60/120Hz 手感一致。

## 6. 性能预算（移动端 WebGL2）

| 项 | 目标 | 依据 |
|---|---|---|
| 帧率 | ≥ 55fps（iPad / 中端安卓） | 手游空战体验底线 |
| 三角面 | ≤ 120k | 13k × 7 机 + 舰船 + 地形 |
| Draw call | ≤ 120 | 需合并战机同材质 mesh 或用 `BatchedMesh` |
| 贴图显存 | ≤ 100MB | KTX2(ASTC/ETC2) 下约为此值 |
| 后处理分辨率 | 0.6–0.75× | bloom 半分辨率 |
| 阴影贴图 | 1024²，仅覆盖战机 | 近距正交相机 |
| PixelRatio | min(dpr, 1.5) | 现在 2.0 在手机上过重 |

三档画质（`Quality.js` 自动探测 + 可手动覆盖）：
- **High**：IBL + 自阴影 + bloom + 4×MSAA + 13k 模型 + 分件动画
- **Mid**：IBL + 无阴影 + bloom(0.5×) + FXAA + 13k 模型
- **Low**：烘焙 AO 的 5k 模型 + 无后处理 + 无 IBL（退回现在的观感，但保证 60fps）

## 8. 验收清单（可量化）

1. 45° 侧光下，机身出现**连续高光带**，而不是散点碎光。
2. 跟随机位下（约 8–10 米等效），**面板线与铆钉可辨**。
3. 机身**上亮下暗至少 2 档**（说明环境反射在工作），且机腹反射偏暖/偏冷有区分。
4. 喷口像素**超过 1.0（HDR）**，经 bloom 形成半径 ≥8px 光晕。
5. 机翼在机身上有**可见投影**（自阴影生效）。
6. 60Hz 与 120Hz 设备上，转向手感一致。
7. 三档画质切换无闪黑、无材质丢失。
