# 音效设计：导弹发射 / 战机爆炸 v1.0

## 0. 为什么不再用 Web Audio 实时合成

原来的实现是几十行节点拼出来的：一段带通噪声 + 一个下滑的正弦，总时长 0.7 s。
问题不在参数，在**层数**。真实录音的信息量来自叠加在一起、各自有独立包络的东西：

- 挂架解锁的机械声（几十毫秒）
- 点火瞬间的宽带脆响（几毫秒）
- 燃料爆燃产生的压力波（低频，几百毫秒）
- 燃烧不稳定造成的噼啪颗粒（持续）
- 燃气喷出的嘶声（持续）
- 导弹离开时的空气吸收（频谱重心一路下移）

这些要逐采样算才做得出来，浏览器里跑不起，也不该在每帧跟渲染抢时间。
所以改成 **Node 离线合成 → 16bit WAV → 运行时只做播放**，和 `bake-terrain.mjs`、
`bake-cloud.mjs` 是同一套路子。

```
tools/bake-sfx.mjs
  ├─ assets/audio/missile-launch.wav   2.90 s  363 KB
  └─ assets/audio/explosion-air.wav    2.60 s  325 KB
```

**版权**：全部是合成信号，没有任何第三方采样，不存在授权问题。
（这一点和 F-16 模型不同，那个是 CC BY-NC-SA，禁止商用。）

## 1. 导弹发射

`t = 0` 是挂架解锁的时刻。

| t | 层 | 做法 | 作用 |
|---|---|---|---|
| 0.000 | 挂架释放 | 1.6 kHz / 3.4 kHz 带通噪声 + 118 Hz 正弦，衰减 7~30 ms | "按下去了"的动作感 |
| 0.035 | 点火脆响 | 1.4 kHz 高通 + 3.2 kHz 提升 7 dB，**起音 1.5 ms**、衰减 11 ms | 整段最响的瞬态 |
| 0.035 | 压力波 | 正弦 30→112 Hz，`tanh(2.4x)` 饱和，衰减 190 ms | 胸口被推一下 |
| 0.035 | 低频尘 | 布朗噪声低通 110 Hz，衰减 320 ms | 让"咚"有厚度而不是纯音 |
| 0.035 | 尾焰主体 | 三层：布朗低通 / 粉噪带通 / 白噪高通，截止频率都在扫动 | "气势"的来源 |
| 0.035 | 燃烧噼啪 | 泊松分布随机脉冲，带通 1.2~5.4 kHz，单个 1~3 ms | 撕裂的颗粒感 |
| 0.035 | 燃气嘶声 | 白噪高通 3.6 kHz，衰减 340 ms | 高压气体的"嘶——" |

三个决定成败的处理：

**① 低频必须饱和。** 30 Hz 的正弦在笔记本和手机上根本放不出来。
`tanh(2.4x)` 会造出 60/90 Hz 的谐波，人耳从谐波里"听出"了那个不存在的低频——
这是小喇叭上做体感的唯一办法。

**② 频谱重心必须随时间下移。** 导弹离机后，高频先被空气吸收掉。
实现是给整条总线挂一个低通，截止频率按秒数指数下降：

```js
f = 800 + 13000 * Math.exp(-t / 0.42)   // 0 s → 13.8k，1 s → 3.7k，2 s → 1.1k
```

没有这一层，声音会一直"糊在脸上"，怎么调都不像飞走了。

**③ 噼啪层不能省。** 只叠三层噪声，得到的是一条平顺的"呼——"，
像吸尘器。加上泊松分布的随机微脉冲之后才有火箭噪声那种粗糙质地：

```js
rate = 26 + 240 * Math.exp(-t / 1.25);   // 起始约 260 次/秒，逐渐稀疏
```

## 2. 战机爆炸

| t | 层 | 做法 |
|---|---|---|
| 0.000 | 起爆脆响 | 高通 850 Hz，**起音 0.6 ms**、衰减 7.5 ms |
| 0.000 | 宽带亮层 | 白噪低通 1.6→6 kHz，衰减 26 ms，高通 260 Hz |
| 0.000 | 低频推力 | 62→38 Hz，`tanh(3.6x)`，衰减 200 ms |
| 0.000 | 中频爆轰 | 带通 2.8→0.56 kHz（Q 0.6），衰减 85 ms |
| 0.000 | 次低频 boom | 21→79 Hz 正弦 + 1.52 倍频，`tanh(3.4x)`，双段衰减 0.40 s + 0.95 s |
| 0.000 | 爆心低频尘 | 布朗噪声低通 62~158 Hz，衰减 340 ms |
| 0.10 | 火球膨胀 | 粉噪低通 240~800 Hz，先涨后落 |
| 0.05~1.15 | 碎片 / 殉爆 | 泊松分布，13% 是较大的二次爆燃 |
| 全程 | 混响 | Schroeder：4 梳状 + 2 全通（反馈 0.72），双声道不同延迟 |

**"低频推力"这一层是 v1.1 加的。** 21 Hz 的次低频只有大箱体放得出来，
手机和笔记本上真正能"推"到人的是 40~90 Hz。单独补一层饱和得更狠的推力，
小喇叭上才有重量感。

**软限幅**是这里唯一"不物理"但必须做的事：

```js
y = tanh(1.35 * x) / tanh(1.35)
```

爆炸的峰值来自起爆瞬间，比后面的 boom 高 10 dB 以上。直接归一化的话，
听起来就是"啪"一声然后什么都没了。tanh 压掉尖峰、把体感抬上来，
相当于挂了一个 4:1 的压限器，密度也就出来了。

## 3. 怎么在没有耳朵的情况下验证

这套东西是逐采样调出来的，改一个增益就可能从"闷"变成"脆"，靠猜不行。
所以 `bake-sfx.mjs` 会打印两个客观指标：

**(1) 分时段频谱重心（centroid）**

| 时间片 | 导弹 | 爆炸 |
|---|---|---|
| 0-32 ms | 416 Hz（挂架释放） | **1386 Hz（起爆）** |
| 32-100 ms | 1533 Hz | 162 Hz |
| 0.1-0.3 s | 1050 Hz | 71 Hz |
| 0.3-0.8 s | 1277 Hz | 54 Hz |
| 0.8-1.5 s | 955 Hz | 41 Hz |
| 1.5 s-尾 | 549 Hz | 37 Hz |

> 第一段必须从 0 开始。起爆瞬态只有 8 ms，从 25 ms 起算等于完全跳过它，
> 会误判成"没有脆度"——v1.1 就是在这个指标上被误导过一次。

判断标准很简单：**起音必须亮、尾部必须暗**。如果 25-75 ms 只有两三百赫兹，
那不是爆炸，是一记闷雷；如果尾部还有一两千赫兹，说明空气吸收没做出来。

导弹在 0.2-0.6 s 有一个回升（1456 Hz），是压力波散掉之后尾焰中高频占比升高的结果，
符合真实发射的听感，不是 bug。

**(2) 最响 100 ms 窗口的 RMS** —— 用来把两段音效的冲击力拉到同一档：

| | 全程 RMS | 最响 100 ms RMS |
|---|---|---|
| 导弹 | 0.088 | 0.294 |
| 爆炸 | 0.257 | 0.624 |

只看全程 RMS 会误判：爆炸拖了 3.4 s，能量积分天然更大。
按最响窗口算，爆炸比导弹高 6.5 dB，所以游戏里导弹给 1.0、爆炸给 0.60，
体感上发射才是主角（毕竟是在自己机翼下面炸响的）。

**(3) 频谱图**（`--spectrogram`）

`Docs/screenshots/sfx-*.png` 是自绘的 STFT 频谱图，纵轴 30 Hz~16 kHz 对数、
横轴为时间。这一步抓到了一个听不出来的 bug——见下面第 5 节。

## 4. 运行时接入

`js/v3/UI.js`：

```js
_master → DynamicsCompressor(threshold -9, ratio 8) → destination
```

总线加限幅器是因为同屏可能有三四架敌机同时被击落，不压会直接数字削波，
那种爆音比音效本身更刺耳。

播放链路：`BufferSource → Gain → StereoPanner → master`

- **空间化**：`Game.audioAt()` 把目标位置投影到相机右向量得到声像（pan），
  按距离做 `260 / (260 + dist)` 衰减。只有一个左右维度，但"远近有别"这一条
  就已经让战场有纵深了。
- **随机化**：每次播放 `playbackRate` 在 0.93~1.07 之间随机，避免连续两次
  听起来是同一段录音。
- **重叠抑制**：0.35 s 内的第 N 发爆炸增益乘 `1/(1+0.5N)`，防止叠成噪音墙。
- **舰船**：同一段采样 `rate 0.78`（更沉、更长）、增益 1.15。
- **导弹**：变调范围只有 ±2%。用户选定的是试听那一刻的版本，
  变调范围再大就会"每次听起来都不是那个声音"。

加载失败（比如用 `file://` 直接打开）会自动退回原来的实时合成，不会静音。

## 5. 踩到的坑

**淡出方向写反了。** 收尾那句写的是 `g = smoothstep(i / fade)`，
`i = 0` 时 `g = 0`——等于在第 3.05 秒把振幅**一步砍到零**。
听感上是结尾"咔"一声，频谱图上是一条贯穿全频段的竖线 + 后面一块 1/f 拖尾。
应该是 `g = 1 - smoothstep(i / fade)`。

**频谱图固定量程等于没有。** 第一版把色标固定在 -78~-12 dB，
结果低频一饱和，整张图是纯白，什么都看不出来。改成按实际峰值自动定
（`top-72 .. top`）之后，各层结构才显示出来。

**tar 分析不能只看总能量。** 一开始按整段做 FFT 积分算频段占比，
得到"中频 0.1%"这种数字——因为 7 ms 的瞬态摊到 3.4 s 里当然没能量。
必须分时间窗口看，才知道起音到底有没有砸下来。

**先量位置再调形状。** 尾焰那次（见 `战机材质与资产-v1.0.md`）的教训同样适用：
不要凭肉眼/耳朵印象猜，先把坐标、频谱、包络打出来。

## 6. 试听与再调

试听：打开 `http://127.0.0.1:8901/index.html?debug`，进游戏后按
**1 = 导弹发射**、**2 = 敌机爆炸**（不用等锁定敌机）。

调音：改 `tools/bake-sfx.mjs` 里 `bakeMissile()` / `bakeExplosion()` 顶部的 `G` 增益表，
重新 `node tools/bake-sfx.mjs --spectrogram` 即可，游戏端不用动（浏览器需刷新缓存）。

| 想改听感 | 改哪里 |
|---|---|
| 发射更"炸" | `G.ignite`、`G.blast`（如果有） ↑ |
| 发射更"沉" | `G.whump`、`G.pressure` ↑ |
| 爆炸更"脆" | `G.crack` ↑，或减小软限幅的 `drive` |
| 爆炸更"boom" | `G.sub`、`G.lowDust` ↑，或增大 `drive` |
| 更远/更近 | 第 ⑧/⑨ 段空气吸收的指数时间常数 |

## 7. v1.1 调音记录：爆炸「更沉、更短促、boom 更重」

用户反馈原文：**「要更沉、更短促，boom 还不够重」**。三件事分别对应三个参数：

| 诉求 | 改法 | 效果 |
|---|---|---|
| 更短促 | 总时长 3.4 → **2.6 s**；次低频双段衰减 0.62/1.55 → **0.40/0.95 s**；碎片窗口 1.85 → 1.15 s；混响反馈 0.80 → 0.72、湿度 0.34 → 0.28 | 包络从 3 秒拖尾变成 2 秒收干净 |
| 更沉 | 次低频 24→86 Hz 改为 **21→79 Hz**；低频尘 80~190 改为 62~158 Hz；中频爆轰衰减 115 → 85 ms（让低频更快接管） | 32-100 ms 的重心 196 → **162 Hz**，0.1-0.3 s 从 77 → **71 Hz** |
| boom 更重 | 新增「低频推力」层（62→38 Hz，`tanh(3.6x)`）；`G.sub` 0.72 → 1.15；`G.lowDust` 0.90 → 1.05；次低频饱和 2.9 → 3.4 | 最响 100 ms RMS 0.464 → **0.624**（+2.6 dB），峰均比 14.2 → **11.4 dB**（更密） |

代价与补偿：
- 起爆脆响被低频压掉了一截，`G.crack` 2.6 → 4.6、`G.blast` 2.3 → 3.6 补回，
  0-32 ms 重心回到 1386 Hz。
- 整体响度上去之后，游戏内爆炸增益按 RMS 配平：0.72 → **0.60**，
  保证发射音（用户已选定的那版）仍然是听觉主角。

> 教训：**频谱重心的第一段必须从 0 开始**。第一版时间片是 25-75 ms，
> 而抗砸的瞬态只有 8 ms，等于完全看不到它，我一度误以为"没有脆度"，
> 白调了一轮。改法是把首段设成 0-32 ms 并用 512 点 FFT（1024 点放不进 32 ms）。
