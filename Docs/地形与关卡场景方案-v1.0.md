---

## 0. 一句话结论

**当前地形的问题不是贴图分辨率不够（其实有 0.53 m/px，够用），而是"一张图重复 77 次 + 零起伏 + 圆形贴片"三件事同时发生。**
修这三件事不需要换美工资源，只需要把"平面贴图"换成"高度场 + 分层混合 + LOD"。

---

## 1. 先定场景：海、陆，还是海陆过渡

参考图 6 张全是内陆（农田、河谷、峡谷），而《中途岛1942》的题材是海岛。这是本方案最大的分叉点。

| 路线 | 画面与参考图的接近度 | 航母/舰船能否复用 | 结论 |
|---|---|---|---|
| A · 纯海洋 + 环礁 | 低（参考图没有海） | 能 | 不推荐 |
| B · **海陆过渡**：航母起飞 → 越海岸线 → 岛屿内陆农田/河谷 | **高** | **能** | ✅ 推荐 |
| C · 纯内陆 | 最高 | 不能（航母无处停） | 只适合后续关卡 |

**推荐 B**，理由有三：

1. 中途岛本身就是环礁——潟湖、沙洲、内陆植被，天然就是"海陆过渡"的地貌，不需要硬编；
2. 保留航母起飞段落，现有的 `carrier.glb` 和舰船编队全部不作废；
3. 一关之内就能演示"海 → 岸 → 田 → 谷"四种地表，是展示画风的最佳载体。

关卡动线建议：`航母甲板起飞（海）→ 低空掠海 20s → 越过礁盘与海岸线 → 内陆农田低空追逐 → 进入河谷/峡谷 → 敌机编队决战`。

## 2. 现状诊断（量化）

先统一尺度。由 `carrier.glb` 的 330 m → 95.7 世界单位推出：**1 世界单位 ≈ 3.45 m**。

| 项 | 现状 | 折算 | 问题 |
|---|---|---|---|
| 地面 | 一个 `PlaneGeometry`，24000×24000 | **83 km 见方**，y 恒为 −18 | 绝对平面，零起伏 |
| 地表贴图 | `yellow-river.jpg` 2048²，`uScale 0.0032` | 平铺周期 **312 单位 = 1.08 km**，全图重复 **77 次** | 同一个河湾图案铺满 83 km，一眼假 |
| 贴图精度 | 2048 px / 312 单位 | **0.53 m/px** | 精度其实够用，问题不在分辨率 |
| 岛屿 | 25 个 chunk 内随机撒圆盘，半径 26–48 单位 | 半径 **90–166 m 的正圆** | 形状是数学圆，无海岸线、无礁盘 |
| 岛屿高度 | 全部贴在同一 y（−17.28） | 高出海面 **2.5 m** | 没有体积、没有阴影、没有层次 |
| 远景 | 无 | 视野尽头直接是海天交界 | 没有地平线层次，画面"平" |
| 空气透视 | 只在 `createOcean` 的 shader 里硬编码 haze | 岛屿贴片**不吃雾** | 岛像贴纸浮在水面上 |
| 碰撞 | 无 | 玩家直接改 position | 加地形后必须补地面检测 |
| 云 | `createClouds()` 返回空 Group | — | 参考图 6406 的云海完全缺失 |

> 一句话：**表现层缺三样（起伏、分层、远景），工程层缺两样（统一雾、碰撞）。**

## 3. 方案选型

| 方案 | 做法 | 优点 | 缺点 | 判断 |
|---|---|---|---|---|
| A · 更大贴图 | 8192² 铺 6 km | 一天能做完 | 内存 250MB+，低空仍糊，仍会重复 | ❌ |
| B · **高度场 + Splat + LOD** | 高度图驱动网格，多地表分层混合 | 兼顾高空整体与低空细节，可控 | 需要一套地形系统（约 5 个模块） | ✅ 采用 |
| C · 真实 DEM + 卫星瓦片 | 接入 Terrain-RGB + 影像瓦片 | 最真，几乎不用美术 | 授权费、网络依赖、加载复杂 | 上线前可选升级 |
| D · 贴图 + 假起伏 | 用贴图阴影假装地形 | 最便宜 | 低空一俯视就穿帮（参考图全是俯视） | ❌ |

**采用 B**，并预留 C 的接口（高度图与贴图都从 URL 读，后期换成真实数据即可）。

## 5. 技术架构

```
js/v3/world/
├── HeightField.js      高度图解码 + 双线性采样 + 法线查询
├── Terrain.js          四叉树 LOD 调度、可见块管理（替掉 updateLand）
├── TerrainMesh.js      按 LOD 生成顶点/索引，写入 BufferGeometry
├── TerrainMaterial.js  Splat 分层混合 + 双频 UV + macro variation
├── Water.js            海 / 河两模式（复用现有 ocean shader）
├── FarRange.js         3 层远山剪影带
└── Atmosphere.js       scene.fog 统一 + 地平线色对齐
```

### 5.1 高度场

- **离线烘焙，运行时只读**：`tools/bake-terrain.mjs` → `assets/terrain/height.png`（1024²，R16 或灰度 16bit）。
  运行时不跑噪声，避免首屏卡顿；后续换真实 DEM 也只需换这张图。
- 生成顺序：`fBm + ridged 噪声（domain warp）→ 丘陵基底 → 沿河曲线做 V 形侵蚀 → 缓坡区轻度平整 → 海岸线曲线裁切 + 海湾`
- **梯田不放在高度场里**：8.8 km 尺度上做高度量化会直接变成「等高线地图」（已实测踩坑），梯田交给 splat 贴图表现（田块真实尺寸 30×80 m，在高度图上只有几个像素）。
- 采样：双线性 + 每 chunk 缓存高度数组，法线由中心差分求出（比网格法线更平滑）。

### 5.2 LOD

沿用现有 `CHUNK = 280`（0.97 km），迁移成本最低。

| LOD | 每块分辨率 | 格边长 | 生效距离 |
|---|---|---|---|
| L0 | 64×64 | 4.4 单位（15 m） | 0–600 单位 |
| L1 | 32×32 | 8.75 单位（30 m） | 600–1200 |
| L2 | 16×16 | 17.5 单位（60 m） | 1200–2400 |
| L3 | 8×8 | 35 单位（120 m） | > 2400 |

- 5×5 环内 L0–L3 混用，总三角面约 **60–80k**，可接受。
- LOD 切换加 `hysteresis`（进出阈值差 15%），避免边缘抖动。

### 5.3 Splat 分层（质感的核心）

三层权重图，共 8 个地表通道：

| 通道 | 地表 | 关键参数 |
|---|---|---|
| R1 | 农田 | 行列纹理明显，色 `#C9BE72` / `#9DB35A` |
| G1 | 草地 | 略深，roughness 0.9 |
| B1 | 林地 | 最深 `#4E6B3A`，法线强（制造"树冠颗粒"） |
| A1 | 岩石/裸土 | 灰褐，法线最锐 |
| R2 | 沙滩 | 浅米，靠近海岸带 |
| G2 | 河床 | 深灰绿，roughness 0.4（湿） |
| B2 | 道路 | 用 splat 画，**不做独立几何**（避免 z-fighting） |
| A2 | 苔草/过渡 | 用于边缘柔化 |

每层：albedo 1024 + normal 1024（normal 只给 L0/L1 采样，远距离跳过省一次纹理读取）。

### 5.4 消除重复感（三招必须同时上）

这是"像不像航拍"的决定性细节，只做一层没用：

1. **Macro variation**：一张 512 的低频噪声，按 1/8 频率采样，把 albedo 亮度与色相调制 ±12%。消除"同一块田重复"的机械感。
2. **双频混合**：`base`（低频，1×）与 `detail`（高频，7×）相乘，近看有颗粒、远看有色块。
3. **按 chunk 哈希随机 UV 旋转 90°×n + 偏移**：破坏网格对齐产生的"接缝节奏"。

### 5.5 河流与道路

- 曲线定义在关卡数据里（3–5 条主干道 + 1 条主河道），用 Catmull-Rom 生成，再按距离场写进 splat 通道。
- 河道额外下沉高度（V 形），并在水面高度处铺一条窄 `Water` 面。
- **道路不要做成凸起的几何**——参考图里的路是"画在地面上的浅色线"，凸起会立刻变成廉价。

### 5.6 远景与空气透视

- **远山用剪影带**，不做网格：3 层低模高度带（距离 6/10/15 km），颜色分别混入 55%/75%/90% 雾色。成本几乎为 0，但地平线层次立刻出来——参考图的远山本质就是雾色剪影。
- 统一 `FogExp2(地平线色 #C3DAE7, 0.00035)`：
  - 1 km → 约 30% 雾；3 km → 约 65%；6 km → 约 88%
- **删除 `createOcean` 里硬编码的 haze**，改用 three 的 fog chunk。现在地形不吃雾、海面吃雾，两者永远对不上。

### 5.7 水面

保留现有 `ShaderMaterial`，加两个 uniform：
- `uMode`：`sea`（大面积，低频法线）/ `river`（窄面，沿曲线 UV，流速更快）
- `uTint`：海水偏青蓝 `#3E7C8C`，河水偏灰绿 `#6E8A94`（与画风定义一致）

### 5.8 植被

- 默认**只用贴图 + 法线**，不加模型（移动端）。
- L0 范围内（600 单位）可加 ≤300 个交叉面片树，实例化渲染，两个 draw call 封顶。
- 树不要做成圆球——参考图的树冠是"绒状深色斑点"，靠贴图密度而非模型。

## 6. 性能与预算

| 项 | 目标 | 说明 |
|---|---|---|
| 地形三角面 | ≤ 80k（实测峰值 74.8k） | L0–L3 混用 |
| 地形 draw call | 实测约 74（2 材质 × 47 块，M2 换单材质 splat 后可降到 ~47） | 空分组已剔除 |
| 贴图显存 | ≤ 60 MB | splat 3×1024 + 8 层 albedo 1024 + 2 normal |
| 首屏地形准备 | < 300 ms | 离线烘焙，运行时只解码 |
| LOD 切换 | 无可见跳变 | hysteresis + 法线由高度场求导（不依赖网格） |
| 帧率影响 | ≤ 3 ms/帧 | 地形是静态几何，主要成本在填充率 |

## 7. 落地顺序

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1** | 高度场 + 四叉树 LOD + 单层草地，替换掉平面与圆岛 | 飞越时有起伏与明暗；不再看到完美的圆 |
| **M2** | Splat 8 层 + 三招去重复 + 法线细节 | 截图缩到 20% 仍像航拍，看不出平铺 |
| **M3** | 河流/道路/梯田 + 远山剪影 + 统一雾 | 有地平线层次，远景不再是"海天一刀切" |
| **M4** | 海陆过渡编排 + 航母衔接 + 地面碰撞与高度警告 | 从甲板起飞 → 掠海 → 上岸 → 进谷，全程无缝 |

### M4 必须补的一个 gameplay 问题

地形有起伏后，**玩家会撞山**。现在 `updatePlayer` 直接写 `position`，没有任何地面检测。必须加：

1. 每帧采样玩家所在位置的地形高度；
2. 离地 < 8 单位时触发"拉起警告"（HUD 红色 + 蜂鸣）；
3. 离地 < 2 单位判定撞毁（进入现有 defeat 流程）。
4. 关卡设计上给低空段留出"谷底通道"，别让玩家被迫贴地。

## 9. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 尺度失衡 | 田块若按真实 500 m 做，会在 48 m 高度下显得过大 | 田块按 87–145 单位做，以"俯视好看"为准，不追求真实 |
| 撞山挫败 | 加地形后难度陡增 | 软地板 + 警告 + 谷底通道 |
| 贴图授权 | 卫星/航拍图有版权 | 原型用 CC0 aerial 贴图；上线换商用授权或自绘 |
| 去重复做过头 | macro 噪声太强会显得脏 | 亮度调制控制在 ±12%，宁弱不强 |
| LOD 裂缝 | 相邻不同分辨率块拼接有缝 | 边缘顶点吸附（skirt 或 stitch），M1 就要做对 |
| 工期 | 地形系统是这几个方案里最重的一块 | 先做 M1 验证手感，确认后再投入 M2/M3 |

### 11.4 与方案的三处偏差（已回改文档）

1. **梯田不进高度场**：量化后变成等高线地图，改由贴图承担。
2. **地形环 3 → 4**：软件渲染验收时发现内陆视角能看到地形环的直边。
3. **draw call 从 ≤12 修正为 ~74**：实际是「每块 1–2 个材质分组」，不是全局共享。

### 11.5 验证方式

- **离线功能校验**（Node + three 桩）：索引越界、分组连续性、属性长度、NaN 全部 0 问题。
- **软件光栅化预览**：把运行时真实生成的网格按追尾相机渲染成图，确认有起伏、有雾、无空洞、无裂缝。
- **1800 帧飞行模拟**：从 z=40 飞到 z=−1400，统计面数峰值与单帧最慢耗时。
- **未验证**：浏览器实机画面。沙箱无外网，`three` 走 CDN importmap 取不到，需本地起服务目视验收。

### 11.6 遗留

- M2：splat 8 层 + 三招去重复 + 法线细节（当前两套材质 + 顶点色，海岸线是硬分界）。
- M3：河流水面、道路、远山剪影、统一 `FogExp2`、删除 ocean 内硬编码 haze。
- 云层仍为空 `Group`。
- `sw.js` 仍指向 v3 之前的旧文件路径（历史遗留，不影响在线使用，但离线预缓存会 404）。

### 13.3 地表合成：为什么不是 splat

原计划是 splat 8 层，实测后改成**单材质 + 着色器合成**，原因有两个：

1. **按三角形分配材质必然锯齿**：8 个通道意味着边界是多边形，粗网格下一眼假（已踩坑，见 12.2）。
2. **没有现成的农田贴图**：现有素材里只有 `yellow-river.jpg` 是真实农田航拍，但它是干旱区黄褐色，直接当 albedo 整片荒漠。

最终方案（三件事都在这一个片元里）：

```
亮度重映射：mLum = luminance(卫星图)
           → 深绿(0.075,0.115,0.045) → 黄绿 → 麦黄(0.56,0.55,0.30)
双频混合：  重映射色 × (0.70 + 0.62 × 高频草地细节)
沙滩混合：  mix(植被色, 沙色, aSand)
```

好处：田块结构来自真实卫星图、颜色可控、**没有任何三角形边界**、draw call 仍是 1。
代价：细节贴图多一次采样；卫星图结构仍是平铺（镜像平铺消除硬缝，但大尺度重复依然存在）。

### 13.4 这一轮踩的新坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 卫星图非无缝 | 平铺处出现笔直的竖直接缝 | 改 `MirroredRepeatWrapping` |
| 卫星图色偏 | 整片荒漠黄 | 亮度重映射到农田色板，不直接用它当颜色 |
| 自定义 ShaderMaterial 不吃 `scene.fog` | 海面与地形雾不一致 | 海面 shader 手动接同参数雾 |
| 环境贴图会整体提亮 | 首版曝光过高 | 曝光降回 1.0，同时压低 hemi |

## 14. M3：水面与远山（2026-11-19 已完成）

### 14.1 水面：从"一块平板"到有深度

关键改动是**让水知道地形在哪**：`bindOceanDepth()` 把高度场以 `DataTexture` 传给水面着色器，片元里换算成水深。

```
depth = 海平面 - 地形高度
depth < 0.2        → discard（陆地底下不画水，水再也不会从地形缝里透出来）
depth 1.5 → 34     → 浅滩色 #3f8f8f 过渡到深水色 #14424f
depth < 3.2        → 岸线泡沫（随水深与时间抖动）
菲涅尔 + 220 次方镜面 → 近处见波纹、远处见天光
```

另加双频法线（`0.085` 与 `0.210` 两个尺度反向滚动），解决单一平铺的"塑料膜"感。

### 14.2 远山：两次做错，第三次才对

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 竖直的"剪影带"（圆柱侧壁） | 高空俯视会看到内壁，像一条漂浮的浅蓝平台 |
| v2 | 环形网格，但山脊用迭代平滑生成 | 128 步后起伏被平均成常数 → 一条平坦雾带 |
| v3 | 环形网格 + **正弦叠加**直接生成山脊 | 有起伏、有层次，俯视也成立 |

教训：**周期性山脊不要用迭代平滑**，IIR 滤波绕一圈会收敛到均值，所有起伏都被吃掉。

颜色不参与 `scene.fog`，直接按距离把山色与雾色 lerp（0.42 / 0.66 / 0.40 三档），用颜色而不是几何表达"远"。

## 16. M7：地形阴影与穿云（2026-11-19 已完成）

### 16.1 地形自阴影：能做，但收益比预期低

先纠正上一节的一个判断错误：地形**不是**自定义 ShaderMaterial，而是 `MeshStandardMaterial` + `onBeforeCompile` 改贴图，`receiveShadow` 一直是开着的。真正缺的是两件事：

1. 地形自己 `castShadow = false` → 阴影贴图里没有山体，山永远不会投影到山谷；
2. 阴影相机只有 ±44 单位 → 只够罩住飞行器。

改成 `castShadow = terrain.castShadow`（默认开，低画质档可关），阴影相机扩到 **±620 单位**（约 2 km，0.6 单位/texel ≈ 2 m）。

结果：**阴影是通的（放一个 70×70 的方块上去，地面投影清晰），但山体互投影几乎看不出来**。原因是太阳仰角高（方向 `(-0.55, 0.78, -0.42)`，仰角约 51°），地形又平缓，20 单位高的丘只投 16 单位长的影子，在这个尺度下基本看不见。

这个方向要真正出效果，得降低太阳仰角（但要和天空贴图的高光位置对齐，属于美术决策），或者把地形起伏做大。**结论：这一步保留，但不要指望它改变观感。**

### 16.2 云影：真正看得见的那一半

既然阴影链路已经打通，把云影也接进去——静态光照下地形再细也像模型，云影掠过大地是"活着"的关键。

复用 `cloud-sea.png` 的 alpha，在世界坐标上以 3200 单位为周期采样，随时间缓慢漂移：

```glsl
vec2 cuv = vWPos.xz / uCloudTile + uCloudTime * (0.0016, 0.0009);
float cover = smoothstep(0.04, 0.52, texture2D(tCloud, cuv).a);
diffuseColor.rgb *= 1.0 - cover * 0.55;
```

两个坑：
- **云海 alpha 覆盖率偏低**，直接用会出现"零星几块"；必须放宽 `smoothstep` 下限，稀薄的云也要压出一点影。
- 自定义 chunk 里 `texture2D` **不吃** `texture.repeat`（那是内置 chunk 通过 `uvTransform` 实现的），周期只能靠 UV 缩放自己算。

### 16.3 穿云

两个问题分开解：

| 现象 | 处理 |
|---|---|
| 穿云时整屏是一张半透明贴片，边缘像糊掉的胶带 | 片元里按到相机的距离淡出：`a *= smoothstep(12, 90, vDist)` |
| 白化不足，读不出"在云里" | 全屏 DOM 遮罩，按**云朵本体**（不是云团中心）的三维距离累加浓度，上限 0.62，120 ms 平滑 |

判定必须用云朵而不是云团中心：云团半径约 300、间距约 1000，用中心判定几乎永远碰不到（实测 opacity 恒为 0）。

| 三角面 | 83.3k（含阴影 pass） |

| 连续飞行 8 秒 | 无异常、无警告 |

`Terrain` 新增 `castShadow` 选项（默认 true），低画质档关掉可以省掉整个地形深度 pass。

## 17. M8：抗锯齿修复 + 相机解耦 + 岸线软化（2026-11-19 已完成）

### 17.1 抗锯齿：确认是 bug，不是配置问题

现象：`Game.js` 里写了 `antialias: true`，但实测 `gl.getContextAttributes().antialias === false`、`SAMPLES === 0`。

原因：`main.js` 为了给 `KTX2Loader.detectSupport()` 提供一个渲染器，在**同一个 canvas** 上先建了 `WebGLRenderer({ canvas, antialias: false })`。一个 canvas 只能有一个 WebGL 上下文，属性以第一次创建为准，所以后建的游戏渲染器拿到的仍是 `antialias: false` 的上下文。

修复：probe 改用一块临时 canvas，用完 `dispose()` + `forceContextLoss()`。

验证：`antialias: true`，`SAMPLES: 4`。这个 bug 的影响面比看上去大——它让**所有**调材质、加贴图、改光照的努力都卡在"边缘永远有锯齿"这个天花板上。

### 17.2 相机：按时间收敛，不再按帧

```js
// 之前：每帧固定收敛 12%，120Hz 上响应比 60Hz 快一倍
this.camera.position.lerp(desired, 0.12);
// 之后
const k = 1 - Math.exp(-8.0 * Math.min(dt, 0.1));
this.camera.position.lerp(desired, k);
```

60 fps 下 k≈0.125，与原来几乎一致；120 Hz 下手感不再变"紧"。

### 17.3 岸线：`discard` 不吃 MSAA

开了 MSAA 之后山的轮廓平滑了，但海岸线仍是台阶状。原因是水面用 `if (depth < 0.2) discard;` 切出陆地边界——**`discard` 是整像素丢弃，MSAA 对它完全无效**（不会做子样本覆盖）。

改成算 alpha 由混合出软岸线：

```glsl
shoreAlpha = smoothstep(-1.2, 2.6, depth);
float nearFade = 1.0 - smoothstep(300.0, 1400.0, fogDepth);  // 远处仍保持不透明
alpha = mix(1.0, shoreAlpha, nearFade);
```

材质相应开 `transparent: true` + `depthWrite: true`（水面是准不透明大平面，写深度才不会和云抢排序），`renderOrder = -1` 保证最先绘制。附带收益：浅水区会透出海底的沙色，形成天然浅滩渐变。

### 17.4 云海底面：灰蓝"天花板"

从下方近乎平视云海平面时，看到的是它朝下的底面，配合距离淡出会变成一整片灰蓝色横带，像天花板的接缝。

修复：按视线与水平面夹角 `graze = 1 - |normalize(toCam).y|` 淡出（`mix(1.0, 0.10, smoothstep(0.50, 0.97, graze))`），同时把底面颜色从 `#a8bccd` 提到 `#cbdaea`。
