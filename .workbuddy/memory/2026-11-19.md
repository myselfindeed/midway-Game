## 战斗机质感重构诊断（未改代码，仅方案）

产出：`Docs/战斗机质感重构方案-v1.0.md`

关键结论：
- 项目有两套战机资产：在用 `assets/models/fighter.glb`（5k 面、单张 JPEG、无 Normal/ORM、paint metalness 0.1），未用 `assets/fighter.glb`（13k 面、KTX2 三贴图 Color/Normal/ORM、25 材质、transmission 座舱、26 分件含副翼/襟翼/舵面）。
- 质感差的根因链：无 `scene.environment`(IBL) → 不敢用金属度 → 材质被压平 → 靠 hemisphere 1.35 补光 → 画面更平更灰。
- `Game.js` 无 shadowMap、无 EffectComposer，直接 renderer.render；ACES 曝光 1.18 偏高。
- 风格不一致：现代战机 + 现代航母(carrier.glb) + 二战 PRD/`fighter.png`(F4U)，需先做路线决策。
- 架构债：`models.js` 507 行混合战机/舰船/海洋/天空/岛屿；`Game.js` 750 行混合玩法与渲染；`main.js` 为 KTX2 检测额外建 probe WebGLRenderer；敌我用 `color.offsetHSL` 改色会破坏贴图。
- 改造顺序建议：抽出 render 层 → 修正启动顺序 → 切 13k 资产 + KTX2 本地化 → IBL/阴影/材质 → 后处理(Bloom+OutputPass+调色+MSAA) → 尾焰分层 → 三档画质。

## M9 Bloom 后期（已实施）

新增：`js/v3/render/PostFX.js`、`vendor/three/examples/jsm/{postprocessing,shaders}/`（r160 官方包，10 个文件）、`tools/shoot.mjs`（可复用 CDP 截图 + 体检脚本，替代之前一次性脚本）。

链路：场景 → HalfFloat 离屏（samples 4）→ RenderPass → UnrealBloomPass（半分辨率）→ OutputPass（ACES + sRGB）。`renderer.toneMapping` 仍留在 renderer 上，OutputPass 每帧读它建 defines。

**四个必须记住的坑**：
1. 自定义 renderTarget 默认 `samples=0`，接 composer 等于把全场景 MSAA 关掉（之前专门修过岸线锯齿）。必须显式 `samples: 4`。
2. `EffectComposer(renderer, rt)` 会拿 `rt.width` 当 CSS 宽，随后 `addPass` 再乘一次 pixelRatio → 纹理放大 dpr 倍。构造后立刻 `composer.setSize(cssW, cssH)` 校正。
3. ACES 内部先乘 `1/0.6≈1.67`，曝光 1.0 接上后期会立刻"洗白"。`toneMappingExposure` 从 1.0 降到 **0.62**。
4. 天空是自定义 ShaderMaterial，`toneMapped:false` 且直接采样 sRGB 贴图。以前直出屏幕刚好抵消，进 HDR 缓冲后必须手写 `srgbToLinear()`，否则整片天空发灰发白。

**HDR 化**：阳光是唯一稳定的 >1 光源（`pow(sd,3000)*16` 硬核 + `pow(sd,120)*1.0` 柔晕）；子弹 ×3.2、尾焰 ×2.8、爆炸 ×2.4（AdditiveBlending）、护盾 ×2.4。阈值定 **0.95**——定 0.88 时白云和海面碎高光整片被挑走，画面糊成白纱。

参数：desktop `0.52 / 0.56 / 0.95`、bloomScale 0.5；mobile `0.34 / 0.45 / 1.02`、bloomScale 0.25、pixelRatio≤1.5、samples 2。`?bloom=0` 只关辉光但仍然走 composer（否则两张图调性不同没法对比）。

**仍未解决**：相机升到 90 高度朝太阳看时，云层出现巨大斜向三角形硬边（关掉 `clouds.group` 即消失，怀疑云毯 `DECK_Y=600/720` 被相机穿越或 billboard 跨近平面裁剪）。正常追尾视角（相机≈48）看不到。


尚未解决（不是 bug）：无 IBL/无阴影导致发灰发平、无田块拼布（待 splat）、水面仍是平面、无远山剪影。

## M7：地形阴影 + 云影 + 穿云（已完成）

**重要纠正**：地形不是自定义 ShaderMaterial，而是 MeshStandardMaterial + onBeforeCompile，receiveShadow 一直开着；缺的是地形自己 castShadow=false + 阴影相机只有 ±44。改成 castShadow 默认开、阴影相机 ±620（0.6 单位/texel）。结论：阴影通了（方块投影清晰），但山体互投影几乎看不见——太阳仰角 51° + 地形平缓，20 单位丘只投 16 单位影。保留但别指望它改变观感。

**云影**（真正看得见的）：复用 cloud-sea.png 的 alpha，世界坐标 3200 单位为周期，随时间漂移。坑：①云海 alpha 覆盖率低，smoothstep 下限要放到 0.04；②自定义 chunk 里 texture2D 不吃 texture.repeat，周期只能靠 UV 缩放自己算。强度 0.55。

**穿云**：①片元按相机距离淡出 a *= smoothstep(12,90,vDist)，避免整屏贴片；②全屏 DOM 遮罩（z-index 4）按"云朵本体"而非云团中心的三维距离累加，上限 0.62。必须按云朵判定——云团半径 300/间距 1000，按中心判定实测恒为 0。

**调试经验（重要）**：
- `paused = true` 时渲染循环停，`renderer.render()` 手动出一帧**截图捕获不到**（compositor 不更新）。要验证运行时改动，必须 paused=false + 把 updatePlayer/updateCamera 换成空函数冻结画面。
- `?debug` 现在会把 `window.__THREE` 也暴露出来，方便控制台造物体验证管线。

开销：139 draw call（含阴影 pass）/ 83.3k 面 / 16 program；连续飞 8 秒无异常。

## M8：抗锯齿修复 + 相机解耦 + 岸线软化（已完成）

**抗锯齿 bug（重要）**：`main.js` 的 probe 渲染器在同一个 canvas 上建上下文，`antialias:false` 被固化，`Game.js` 的 `antialias:true` 完全无效（实测 SAMPLES=0）。修法：probe 用独立临时 canvas + dispose + forceContextLoss。修复后 `antialias:true, SAMPLES:4`。

**相机**：`lerp(desired, 0.12)` 按帧收敛 → `1 - exp(-8*dt)`，60fps 下 k≈0.125 与原值一致，120Hz 不再变"紧"。

**岸线**：`discard` 不参与 MSAA（整像素丢弃），海岸线必然是台阶。改成 `shoreAlpha = smoothstep(-1.2, 2.6, depth)` 输出 alpha，材质开 transparent + depthWrite + renderOrder=-1；用 nearFade(300~1400) 保证远处仍不透明。附带浅滩透出海底沙色。

**云海底面**：平视云海看到灰色底面 → 按 graze 角度淡出 + 底色 #a8bccd→#cbdaea。

清理：删 models.js 50 行死代码（createIsland/discMesh/sharedMap/repeated + 空 createClouds）；停止预载 destroyer.png（781KB，已无引用）。
实测：145 draw call / 87.8k 面 / 16 program / 8 秒无异常。

## M10 战机材质修复 + 换 F-16 资产

**"顺光还是黑的"不是光照问题，是反照率问题。**
用 `MeshBasicMaterial({map})` 直接输出 baseColor 贴图，机身仍是纯黑 → 贴图本身就是 ≈0.05 的深灰涂装。
所以调光、加补光、改 metalness 都救不了，只能在反照率上动手。

顺带挖出一个死代码 bug：`if (m.color && !m.emissiveIntensity) m.color.multiplyScalar(2.1)`——
`emissiveIntensity` 默认就是 1，取反恒为 false，**这个分支从来没执行过**。而且 color 是纯白，乘 2.1 也救不了 0.05 的贴图。

修复（`models.js` → `fighterMaterial`）：
- 有 baseColor 贴图的蒙皮：`color ×4.5`、`metalness 0.15`、`roughness 0.55`、`envMapIntensity 1.4`
- 系数实测：×4 中灰有层次 / ×7 偏白 / ×11 冲成纯白丢细节
- Glass：glTF 默认 `metalness=1`，玻璃按金属算＝不反光不透光的灰板。改 0.1 / 0.06 / opacity 0.46 / depthWrite off
- 敌我用色调区分：`color.multiply(0.82,0.52,0.46)` → 砖红，与玩家浅灰拉开

**F-16 资产**：`assets/models/f16.glb`，30,272 面 / 4 材质 / 3 张 PNG（5.2MB），来自 bohmerang（Sketchfab）。
- 授权 **CC BY-NC-SA 4.0（禁止商用）**，只能用于原型演示，上线前必须替换
- 节点自带 `landingOff`/`landingOn`，飞行时隐藏 `landingOn*` 即收起落架
- 没有副翼/襟翼分件节点（原隐身机有 rudder/stabilator），分件动画需要重新找资产
- glTF 导入的 `metalness` 默认是 **1.0**，不显式改就永远是金属黑

**M10 补记：两个隐藏问题**
1. `normalizeFighterModel` 写死 `rotation.y = PI`（假定机头朝 +Z）。F-16 的包围盒 `size.x=150.9 > size.z=93.9`，
   机头朝 X 轴 → 飞机横着飞 90°。追尾视角下看着"只是机头偏了一点"，其实完全错向。已改为按长轴判断补 90°。
2. F-16 资产无尾焰节点，`getObjectByName('exhaust')` 恒为 undefined，加速没有视觉反馈。
   在 `instantiateFighter` 里补了一个锥体（+Z 机尾、亮度 1.5）。亮度给 2.8 会被加色 + bloom 糊成直径两倍于机身的白球。

**M10 尾焰返工（第三次才对）**
现象："喷口一片黑，完全看不到火焰"，但对象存在、visible=true、位置数值也对。
真因不是方向，是**层级变换**：`flame(Group, position=0)` 的子物体 `cone.position.z=2.68`，
而 Game 用 `exhaust.scale.set(b,b,b*pulse)` 控制长度 → **group.scale.z 把子物体的 position.z 一起乘了**，
实测局部 z 从 2.28~3.08 压到 1.48~2.00，机尾在 2.65，整支火焰缩进机身被遮挡。
修法：自定义 BufferGeometry，锥体从 z=0 长到 z=length，`flame.position.z=2.38` 钉在喷口，scale.z 只改长度不动起点。
另：颜色从青白 #7ef6ff（等离子感，和灰机身/暖阳光不搭）换成琥珀 #fff0d2 + #ff8c3a 双层；敌机偏红。
巡航 scale 0.72 / 加力 1.5，长度差 2 倍作为加速反馈。
教训：排查"看不见"先查世界坐标变换链，别靠肉眼判断方向（我一度以为 ConeGeometry 的 ±90° 反了，白改一轮）。

**M10 尾焰第二轮：喷口定位 + 马赫环**
"火焰不在喷气口"是坐标问题。把 airframe 全部顶点换算到机体局部坐标后按 z 切片统计：
喷口唇口 **z≈2.45**、截面中心 **y≈-0.15**（机身中轴不在 y=0），之前写 (0,0,2.38) 所以浮在喷口上沿。
统计时要注意排除垂尾（|y| 大、x 很薄）和平尾（|x| 大）的顶点，否则截面中心会被拉偏。

马赫环用 ShaderMaterial 在几何 z 轴上做周期调制：
`band = 0.5+0.5*sin(vT*freq - t*5)`，`rings = mix(1, 0.12+0.88*pow(band,6), uRingAmp)`。
pow 6 把正弦削成尖峰，环外压到 0.12——对比不够就只是一条均匀光带。
`vT = position.z/uLength` 用几何局部坐标，scale.z 改长度时环不会变形（自定义几何没 uv，正好不用）。
头部 4% 渐入（smoothstep(0,0.04,vT)）消掉起点那圈"圆箍"：锥体起点顶点法线朝径向，侧视会成一道硬边亮环。

尺寸按真实比例：1 单位=3.45m，F-16 加力焰 4–5m → 1.2~1.5 单位（机长 30%）。内核 0.70 / 包络 1.00。
颜色 #fff3dc + #ff8c3a（玩家）、#ffd6b8 + #ff3f18（敌机）。

两个坑：`ShaderMaterial` 的 vec3 uniform 不认 THREE.Color，必须转 Vector3；
时间相位用共享 uniform FLAME_TIME 由 Game.update 每帧推，别每架飞机各存一份。

另：headless 偶发全黑截图（HUD 正常、3D 全黑），重跑一次即恢复，不是代码问题。

## M11 修"屏幕一闪一闪"（严重 bug）

现象：用户试玩反馈屏幕间歇闪烁。逐帧采样证实**整帧输出全黑**，约每 5~10 帧一次。

排查路径（记下来，这类问题容易走错方向）：
1. 冻结场景（清空 updatePlayer/updateCamera/updateLand/clouds.update）→ 亮度波动仅 0.36/255，排除渲染管线逻辑。
2. 正常飞行 → 整体亮度序列出现 4.94（近黑）。用 CDP 连拍 + 自写 PNG 解码确认（`tools/flicker.mjs`）。
3. 页面内 `gl.readPixels` 逐帧采样复现 → 排除截图工具（WebGL 默认不保留绘制缓冲）的假象。
4. 加 `gl.finish()`、显式 `bindFramebuffer(null)`、开 `preserveDrawingBuffer` → **仍为 0**。
5. 监听 `webglcontextlost` → 无事件；帧间隔稳定 33ms → 不是掉帧/上下文丢失。
6. **`samples: 4` → 0，0 帧全部消失。再用 2 验证，仍偶尔出现。**

结论：**HalfFloat render target + 任何 MSAA 在 Chrome/Metal 下会间歇性解析失败，整帧全黑。**
不是本项目代码逻辑问题，但必须规避。

修复：`samples: 0`，抗锯齿改用 **FXAA**（`ShaderPass` + `FXAAShader`，放在 OutputPass 之后，
在 sRGB 空间做边缘检测，线性 HDR 空间做会出暗边）。FXAA 的 `resolution` 必须传**物理像素倒数**（1/(w*dpr)）。
画质对比：机翼/垂尾/海岸线边缘与 4×MSAA 肉眼差别很小，文字标识仍清晰。

代价与收获：之前专门为"岸边硬锯齿"修的 MSAA 只能放弃，但换来了稳定性。
好在本项目的海岸线本来就是 alpha 混合软边（不是几何锯齿），FXAA 足够。

`preserveDrawingBuffer` 最终**去掉**了（诊断期临时开过）：关掉 MSAA 后截图已经稳定，不必付那个带宽代价。
`tools/flicker.mjs` 保留，以后怀疑闪烁可以直接跑：`SETUP_FILE=... node tools/flicker.mjs 14 100`。

## M12 音效重做：导弹发射 / 战机爆炸

用户诉求："真实战斗机发射导弹的气势"+"击败敌机带 boom 的爆炸声"。

**结论：实时 Web Audio 合成做不出"真实"，改成 Node 离线烘焙 WAV。**
原实现是 0.7 s 的"带通噪声 + 下滑正弦"，层数不够。真实录音的信息量来自
5~7 层各自有独立包络的信号，必须逐采样算 → `tools/bake-sfx.mjs`（零依赖）。

产物：`assets/audio/missile-launch.wav`（2.9 s）、`explosion-air.wav`（3.4 s），
32 kHz 16bit stereo，363 + 425 KB。全部合成信号，无第三方采样、无授权问题。

三个关键技术点：
1. **低频必须 tanh 饱和**：30 Hz 在手机/笔记本上放不出来，`tanh(2.4x)` 造出 60/90 Hz 谐波，
   人耳从谐波里"听出"不存在的低频。这是小喇叭上做体感的唯一办法。
2. **频谱重心必须随秒数下移**（空气吸收）：`f = 800 + 13000*exp(-t/0.42)`，
   0 s→13.8k / 1 s→3.7k / 2 s→1.1k。没有这层，声音永远像"糊在脸上"，不像飞走了。
3. **泊松分布的噼啪层不能省**：只叠三层噪声是平顺的"呼——"，像吸尘器；
   加随机微脉冲（起始 260 次/秒逐渐稀疏）才有火箭噪声的粗糙质地。

爆炸侧：起爆脆响 0.6 ms 起音 + 宽带亮层 32 ms + 中频爆轰 2.8→0.56 kHz +
次低频 24→86 Hz 双段衰减（0.62 s + 1.55 s）+ 碎片泊松 + Schroeder 混响。
**整段软限幅 `tanh(1.35x)` 必须做**：峰值来自起爆瞬间，比 boom 高 10 dB+，
直接归一化会变成"啪一声然后没了"。

**没有耳朵怎么调**：`bake-sfx.mjs` 打印分时段频谱重心 + 各倍频程柱状条。
判据只有一条——起音必须亮、尾部必须暗。爆炸 25-75ms 466 Hz → 尾段 40 Hz；
导弹 1579 Hz → 547 Hz。另加"最响 100 ms RMS"用来把两段音效的冲击力拉平
（导弹 0.294 / 爆炸 0.464 → 游戏内增益 1.0 / 0.72）。

抓到两个 bug：
- **淡出方向写反**：`g = smoothstep(i/fade)` 在 i=0 时为 0，等于在第 3.05 s 把振幅一步砍到零，
  结尾"咔"一声。频谱图上是一条贯穿全频段的竖线 + 后面 1/f 拖尾。应为 `1 - smoothstep()`。
- **频谱图固定色标等于没有**：-78~-12 dB 时低频一饱和整张图纯白。改成按峰值自动定（top-72..top）。

运行时接入（`UI.js`）：总线加 DynamicsCompressor 限幅（多架同时被击落会削波）；
`Game.audioAt()` 把目标投影到相机右向量做 pan、按 260/(260+dist) 衰减；
每次播放 rate 随机 0.93~1.07；0.35 s 内重叠的爆炸增益乘 1/(1+0.5N)；舰船 rate 0.78。
加载失败自动退回原合成音。

试听：`?debug` 下进游戏按 1 = 发射、2 = 爆炸。
文档：`Docs/音效设计-v1.0.md`。

**M12 补记：爆炸按"更沉、更短促、boom 更重"重调**
- 时长 3.4→2.6 s，次低频双段衰减 0.62/1.55→0.40/0.95，碎片窗口 1.85→1.15，混响反馈 0.80→0.72。
- 基频 24→86 改为 21→79 Hz，低频尘 80~190 改 62~158，中频爆轰衰减 115→85 ms。
- **新增"低频推力"层**（62→38 Hz，tanh 3.6）：21 Hz 只有大箱体放得出，
  小喇叭上真正能"推"到人的是 40~90 Hz，必须单独补一层。
- 最响 100ms RMS 0.464→0.624，峰均比 14.2→11.4 dB（更密）。游戏内增益相应 0.72→0.60。
- 起爆被低频压掉一截 → G.crack 2.6→4.6、G.blast 2.3→3.6 补回，0-32ms 重心 1386 Hz。

**指标教训**：频谱重心的首段必须从 0 开始。原来首段是 25-75 ms，而抗砸瞬态只有 8 ms，
等于被完全跳过，我据此误判成"没有脆度"并白调一轮。改成 0-32 ms + 512 点 FFT 才对。
另：对数频率映射到单根 FFT bin 会画出假的横向条纹（像梳状滤波），已改为相邻 bin 线性插值。

**M12 定版**：用户先后确认 `missile-launch.wav`（2.9 s）与 `explosion-air.wav`（2.6 s）两段都用当前版本。
两段的游戏内随机变调都收窄到 ±2%（导弹 0.98~1.02、爆炸 0.975~1.025）——
既然选定的是试听那一刻的声音，变调范围就必须小到听不出差异。
舰船仍走显式 rate 0.78（在 ±2.5% 基础上继续下压），作为吨位区分。
加载失败时仍回退到旧的实时合成，不会静音。

## 修复手机浏览器双击缩放（快速点按钮放大画面）
